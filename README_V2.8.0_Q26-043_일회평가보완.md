# 하나금속 제안관리 V2.8.0 — Q26-043 1차·2차 평가 1회 보완

## 목적
- Q26-043 단 한 건에 시스템 관리자 전용 점수 보완 입력창을 추가합니다.
- 1차(제안자 자기평가) 6개 항목과 2차(팀장평가) 6개 항목을 **한 번의 저장**으로 보완합니다.
- 1차 가중총점은 최소 50점 이상, 2차는 50점 미만이어도 점수 기록 자체는 가능합니다.
- 기존 3차 심사점수, 승인·반려 기록, 채택/미채택 결과, 포상금 및 지급정보는 **전혀 재계산하거나 변경하지 않습니다.**
- 관리자 입력임을 별도 감사 테이블에 원래 점수·수정 점수·사유·관리자·시각과 함께 남깁니다.

## 적용 순서
1. **운영 DB 백업 권장.** SQL 실행 전 Q26-043의 기존 점수·결재 상태를 확인하세요.
2. Supabase → SQL Editor → New query에서 `sql/V2.8.0_Q26-043_1차2차_한건보완.sql` **전체 코드**를 붙여넣고 한 번 실행합니다. 설치 자체로 기존 점수는 바뀌지 않습니다.
3. 마지막 결과 `status_ready`, `save_ready`, `guard_ready`가 모두 `true`, `already_used_count`는 처음에 `0`인지 확인합니다. 오류가 나면 다음 단계로 진행하지 않습니다.
4. GitHub 저장소에서 압축 안의 아래 네 파일만 **같은 경로**에 업로드/교체합니다.
   - `index.html` (교체)
   - `js/app.js` (교체)
   - `js/services/store.js` (교체)
   - `js/oneoff/q26043-core.js` (**새로 추가**)
5. 배포 후 `Ctrl + F5`. 시스템 관리자 로그인 → Q26-043 상세 → **`1·2차 점수 한시 보완`** 또는 `#admin/q26043` 경로로 진입합니다.
6. **두 평가표 각 6개 항목**, 보완 사유를 입력한 뒤 확인 체크 → `Q26-043 점수 한 번 저장`을 누르세요.
7. 저장 후 점수 재조회가 확인되면 입력창이 잠깁니다. 한 번 완료한 뒤 다시 저장할 수 없도록 서버에서도 차단합니다.

## 주의
- 기존 부서장·심사위원이 실제로 매긴 점수처럼 보일 수 있으므로, 이 점수는 **관리자가 이번 한 번 보완 입력한 기록**이라는 점을 감사 기록과 화면 안내로 구분했습니다.
- 2차 점수를 입력해도 기존 심사단계·상신·포상금·3차 점수는 자동으로 변경되지 않습니다. 기존 심사가 완료된 제안의 처리결과와 점수 간 차이는 별도 관리자 검토가 필요합니다.
- 다른 제안은 이 기능의 대상이 아닙니다. 신규/기존 평가 흐름의 일반 권한과 점수 기준도 바뀌지 않습니다.
- `js/config.js`, 기존 `reports`, `operations`, CSS 폴더를 삭제하거나 수정할 필요 없습니다.
- 보안상 임의의 관리자 비밀번호나 API 키를 입력할 필요가 없습니다.

## 검증 범위
- 1차 최소 50점 / 2차 하한 없음 / 6개 정수 점수 검증 / 관리자 권한 / 1회 저장 / 원래 3차·결과·포상·결재 잠금 보존을 로컬 데모 저장소에서 검증했습니다.
- SQL은 컬럼·권한·특정 제안 식별·트리거를 정적으로 확인했으나 **실제 운영 PostgreSQL/Supabase에서 실행하지 못했습니다.** 운영 SQL 성공 여부는 위 3개 확인값과 적용 후 재조회로 확인해야 합니다.
- 기존 전체 검사에서 남아 있는 브랜드 버전, 대시보드 훅, 포상 구간, 인쇄 결재선 테스트 4건은 이번 기능과 별개로 남습니다.
