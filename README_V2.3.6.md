# 하나금속 제안관리 V2.3.6 결재진행 표시/레코드 복구 패치

## 수정 내용
- 공개 상세/인쇄 화면이 `approval_records` 테이블을 직접 조회하지 않고 `get_public_approval_progress()` RPC로 안전하게 조회합니다.
- V2.3 컷오버 이후 전자결재 대상 중 누락된 활성 5단계 결재레코드를 자동 복구합니다.
- 현재 관리자 화면에 연결된 결재자(부서장/해당부서 임원/주관부서/대표이사)를 진행중 레코드에 다시 동기화합니다.
- 이미 대표이사 최종승인 완료된 제안은 소급 재결재시키지 않습니다.
- 현재 결재차례의 이메일 큐를 보강합니다.

## 적용 순서
1. Supabase SQL Editor → New query
2. `sql/V2.3.6_결재진행_공개조회_레코드복구.sql` 전체 실행
3. 첫 확인값 `public_approval_progress_rpc = true` 확인
4. 두 번째 결과표에서 Q26-036 등 최근 제안의 1~5단계 상태/assigned_name 확인
5. GitHub에 `index.html`, `js/app.js`, `js/services/store.js` 덮어쓰기
6. 기존 `js/config.js`는 변경/삭제하지 않기
7. Commit 후 1~3분 대기 → Ctrl+F5

## 정상 표시 예시
- 담당: 작성완료 · 장영훈
- 부서장: 대기 · 장영훈
- 해당부서 임원: 대기 · 지정 임원명
- 주관부서: 대기 · 지정 주관부서 결재자명
- 대표이사: 대기 · 지정 대표이사명
