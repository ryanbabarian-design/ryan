# 하나금속 제안관리 V2.3 - 신규건 전자결재 + 결재알림 + 이메일

## 최종 결재선

`담당(제안 제출 시 자동작성) → 부서장 → 주관부서 → 대표이사`

- 담당: 별도 계정/서명 없음. 제안 제출 즉시 제안자명으로 `작성완료` 처리
- 부서장: 제안자의 소속부서별 결재자 계정 연결
- 주관부서: 전사 공통 결재자 계정 연결 권장
- 대표이사: 전사 공통 결재자 계정 연결 권장

## 가장 중요한 변경

V2.3 SQL을 **최초 실행한 시점 이전에 이미 등록되어 있던 제안은 전자결재 대상에서 전부 제외**됩니다.
기존 제안은 삭제되지 않으며 접수현황/검색/심사/인쇄는 그대로 사용할 수 있습니다.

V2.3 적용 후 새로 접수하는 제안부터만 `approval_required=true`가 자동 설정되어 결재함, 빨간 배지, 1/3/7일 지연관리, 이메일 알림 대상이 됩니다.

## 1. Supabase SQL 적용

Supabase → SQL Editor → New query에서 아래 파일 전체를 실행합니다.

`sql/V2.3_결재알림_이메일_신규건만.sql`

기존 V2.0/V2.1/V2.2 SQL은 삭제하거나 다시 실행하지 않습니다.

정상 실행 후 활성 결재단계는 정확히 4행이어야 합니다.

1. 담당 / auto_author=true
2. 부서장
3. 주관부서
4. 대표이사

SQL 실행 직후 `new_approval_targets`가 0이어도 정상입니다. **SQL 실행 이후 새 제안을 하나 등록하면 1로 증가**해야 합니다.

> V2.2의 3번 단계는 `공장장`이었으므로 V2.3 최초 적용 때 3번 단계의 기존 결재자 배정은 안전을 위해 자동 해제됩니다. SQL 적용 후 `주관부서` 결재자 계정을 다시 연결하세요.

## 2. GitHub Pages 파일 덮어쓰기

ZIP의 아래 항목만 기존 GitHub 저장소 루트에 덮어씁니다.

- `index.html`
- `css/`
- `js/`

기존 `js/config.js`는 삭제하거나 덮어쓰지 않습니다. 이 패키지에는 `config.js`가 포함되어 있지 않습니다.

## 3. 실제 결재자 계정 연결

Supabase → Authentication → Users에서 결재자 계정을 먼저 만듭니다.
그 다음 제안관리 웹 → 관리자·결재 → 전자결재 설정에서 연결합니다.

- 부서장: 부서별로 각각 연결
- 주관부서: `전체 부서`로 연결 권장
- 대표이사: `전체 부서`로 연결 권장

담당 계정은 만들지 않습니다.

## 4. 화면 알림

- 상단 `관리자·결재` 버튼에 본인 결재 대기 빨간 숫자 표시
- 관리자 하위 `내 결재함`에도 대기 숫자 표시
- 결재자 로그인 직후 대기건이 있으면 안내 팝업
- 대기 1일 이상: `결재 필요`
- 대기 3일 이상: `결재 지연`
- 대기 7일 이상: `장기 미결재`
- 시스템 관리자 화면에 3일+/7일+ 전체 지연건수 표시
- V2.3 이전 제안 상세에는 `전자결재 대상 아님` 표시

## 5. Resend 이메일 준비

Edge Function 소스:

`supabase/functions/approval-email/index.ts`

Supabase Edge Function 이름은 `approval-email`로 생성/배포합니다.

Supabase Edge Function Secrets에 다음 값을 등록합니다.

- `RESEND_API_KEY`: Resend에서 만든 API Key
- `RESEND_FROM_EMAIL`: 인증된 발신주소 (예: `하나금속 제안관리 <proposal@proposal.company.com>`)
- `SITE_URL`: `https://ryanbabarian-design.github.io/ryan`
- `APPROVAL_EMAIL_HOOK_SECRET`: 직접 만든 충분히 긴 임의 문자열

`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase hosted Edge Function의 서버 환경변수를 사용합니다. 서비스 키를 GitHub/브라우저 코드에 넣지 않습니다.

이메일 큐는 다음 시점에 자동 생성됩니다.

- 신규 제안 접수 → 부서장
- 부서장 승인 → 주관부서
- 주관부서 승인 → 대표이사
- 1/3/7일 미결재 → 해당 결재자
- 7일 미결재 → 시스템 관리자도 추가 알림

메일 실패는 결재 저장을 롤백하지 않습니다. 관리자 → `메일알림`에서 실패내용을 확인하고 재전송할 수 있습니다.

## 6. Cron

`sql/V2.3_이메일Cron_설정_예시.sql`은 예시 파일입니다. 실제 Project URL과 Hook Secret을 Supabase Vault에 저장한 뒤 실행합니다.

- 이메일 큐 발송: 1분마다 Edge Function 호출
- 미결재 1/3/7일 큐 생성: 매일 00:00 UTC (= 한국시간 09:00) 실행

## 7. 적용 후 실운영 테스트

1. V2.3 SQL 실행
2. 부서장 / 주관부서 / 대표이사 계정 연결
3. 새 테스트 제안 1건 등록
4. 담당이 자동 `작성완료`인지 확인
5. 부서장 계정 로그인 → 빨간 대기건 1 확인 → 승인
6. 주관부서 계정 로그인 → 방금 건이 다음 결재로 들어오는지 확인
7. 주관부서 승인 → 대표이사 결재함 확인
8. 대표이사 승인 → 전체 완료 확인
9. V2.3 적용 전에 만든 제안은 결재함에 나오지 않는지 확인
10. Resend 설정 후 메일 발송 성공기록 확인
