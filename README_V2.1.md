# 하나금속 제안관리 V2.1 — 결재자 본인서명 / 순차 전자결재

V2.0 통합운영 버전에 전자결재 권한 분리를 추가한 필수 보안 패치입니다.

## 핵심 변경
- 시스템 관리자와 결재자 권한 분리
- 결재단계별 실제 로그인 계정 연결
- 부서별 팀장/부서장 지정 가능
- 전사 담당·공장장·대표이사는 `전체 부서`로 지정 가능
- 본인에게 지정된 단계만 승인/반려 가능
- 이전 단계가 모두 승인된 뒤에만 다음 단계 활성화
- 이미 승인/반려한 결재는 다시 덮어쓸 수 없음
- 승인자 이름과 처리시간 자동 기록
- 시스템 관리자도 결재자로 별도 지정되지 않으면 서명 불가
- 결재자 전용 `내 결재함` 제공
- 결재자 계정은 제안 심사값·목표·설정·삭제 권한 없음

## 적용 순서
### 1. Supabase SQL
기존 V2.0 SQL은 삭제하거나 다시 실행하지 마세요.
Supabase → SQL Editor → New query에서 `sql/V2.1_전자결재_권한분리_실행.sql`만 전체 실행합니다.

정상 실행 뒤 마지막 결과에서:
- `approval_assignments` 테이블 확인
- `link_approver_rpc = true`
- `secure_approval_rpc = true`
- `approval_inbox_rpc = true`
가 표시되면 됩니다.

### 2. GitHub 업로드
GitHub 저장소에서 Add file → Upload files로 다음만 덮어씁니다.
- `index.html`
- `assets/`
- `css/`
- `js/`

`js/config.js`는 이 패키지에 없으며 기존 GitHub 파일을 그대로 유지해야 합니다.

### 3. 실제 결재자 계정 생성
Supabase → Authentication → Users → Add user에서 결재자별 계정을 만듭니다.
- 이메일
- 개인 비밀번호
- Auto Confirm 활성화 권장

### 4. 시스템관리자가 결재자 연결
웹사이트 → `관리자·결재` → 시스템 관리자 로그인 → `전자결재 설정`

`결재자 계정 연결`에서:
- 이메일: Auth에 만든 이메일
- 이름: 출력/서명에 표시할 실제 이름
- 본인 결재단계: 담당 / 팀장 / 공장장 / 대표이사 등
- 적용부서: 부서장·팀장은 해당 부서, 전사 결재자는 전체 부서

예시:
- 담당 홍길동 → 담당 → 전체 부서
- 가공팀장 김가공 → 팀장 → 가공
- 압연팀장 박압연 → 팀장 → 압연
- 공장장 이공장 → 공장장 → 전체 부서
- 대표이사 최대표 → 대표이사 → 전체 부서

### 5. 결재자가 서명
결재자는 웹사이트 → `관리자·결재`에서 본인 이메일/비밀번호로 로그인합니다.
`내 결재함`에 본인에게 배정된 제안만 표시됩니다.

- 이전 단계 승인 전: 처리 버튼 비활성/대기 안내
- 본인 차례: `결재 검토` → 승인 또는 반려 → `본인 전자서명 저장`
- 처리 후: 이름과 처리일시가 전자결재 진행 및 인쇄 제안서에 반영

## 주의
- 한 결재단계+부서에는 한 명의 결재자만 지정됩니다. 같은 범위에 새 사람을 연결하면 기존 배정이 교체됩니다.
- 시스템 관리자 계정과 실제 결재자가 같은 사람이라면 그 관리자 이메일도 결재자 연결에서 해당 단계에 별도로 배정해야 서명할 수 있습니다.
- 기존 2019~2026년 제안자료와 사진, 심사자료는 삭제하지 않습니다.
