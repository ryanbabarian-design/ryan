## 처리 기준

- 회수는 대표이사가 아직 처리하지 않은 미지급·지급예정 건만 가능하다. 실제 승인·반려 서명이나 지급완료 기록이 있으면 차단한다. 같은 화면을 다른 사람이 먼저 변경했으면 최신 자료를 다시 확인해야 한다.
- 과거 기록이 없는 결재·평가일은 만들어 표시하지 않는다. 실제 조회 실패와 실제 기록 없음은 구분한다.
- 초안은 사용 중인 브라우저의 저장소에 보관한다. 수정번호(PIN)와 공개 동의는 저장하지 않으며 복원 후 다시 입력·확인한다.
- 이미 시도한 신규 제출은 원본 내용·사진과 같은 요청으로만 재확인한다. 접수 중단 후에도 이전 제출 결과와 저장된 접수번호는 복구할 수 있다. 새 제안 생성은 서버의 접수 운영 설정을 따른다.
- 여러 탭의 서로 다른 초안을 별도로 보존한다. 폐기한 초안을 늦게 도착한 응답이나 다른 탭이 되살리지 않도록 처리한다.
- 사진 재시도는 원본 바이트가 같은 기존 업로드만 재사용한다.
- 대표이사 미결재 안내는 기존 정책대로 7일(168시간) 경과 후 묶음 1통이다. 같은 대기 주기를 반복 안내하지 않는다. 기존 제안의 직접 상신도 검증된 담당자·대기 주기에만 포함한다.
- 메일이 접수됐는지 확인할 수 없는 응답은 ‘발송 확인 필요’로 보존한다. 확인 전에 재발송하거나 그 메일의 대상 목록을 바꾸지 않는다.
- 회수의 상세 사유는 관리자 전용 이력에 보존한다. 공개 타임라인에는 중립적인 상태 변경만 표시한다.
- 데모 모드에서는 새 트랜잭션 기능의 서버 처리 대신 실제 연결이 필요하다는 안내를 표시한다.
