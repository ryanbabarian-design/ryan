# 하나금속 제안관리 V2.3.5 — 해당부서 임원 5단계 결재

## 최종 결재선
담당(자동작성) → 부서장 → 해당부서 임원 → 주관부서 → 대표이사

## 배정 기준
- 담당: 제안 제출 시 제안자명으로 자동작성 완료
- 부서장: 제안자의 소속부서와 정확히 일치하는 계정
- 해당부서 임원: 제안자의 소속부서와 정확히 일치하는 계정
- 주관부서: 전체 부서 공통 계정
- 대표이사: 전체 부서 공통 계정

## 데이터 보호
- V2.3 적용 이전 과거 제안은 계속 전자결재/메일 대상 제외
- 기존 주관부서/대표이사 step ID를 유지하므로 기존 계정 연결을 보존
- 대표이사 최종승인이 이미 완료된 제안은 새 임원 결재를 소급 강제하지 않음
- 아직 진행 중인 V2.3 신규 제안에는 새 임원 단계만 추가

## 적용 순서
1. Supabase → SQL Editor → New query
2. `sql/V2.3.5_해당부서임원_5단계결재_실행.sql` 전체 실행
3. 결과 첫 표가 정확히 5줄인지 확인
   - 1 담당
   - 2 부서장
   - 3 해당부서 임원
   - 4 주관부서
   - 5 대표이사
4. GitHub에 아래 파일 덮어쓰기
   - `index.html`
   - `js/app.js`
   - `js/core.js`
   - `js/print.js`
   - `js/services/store.js`
5. 기존 `js/config.js`는 삭제/수정하지 않음
6. Commit 후 1~3분 뒤 Ctrl+F5
7. 관리자 → 전자결재 설정에서 각 부서의 `해당부서 임원` 계정을 추가 연결

## 결재자 연결 예
- 생산관리 / 부서장 / 생산관리 부서장 계정
- 생산관리 / 해당부서 임원 / 생산관리 담당 임원 계정
- 압연 / 부서장 / 압연 부서장 계정
- 압연 / 해당부서 임원 / 압연 담당 임원 계정
- 주관부서 / 전체 부서 / 공통 계정
- 대표이사 / 전체 부서 / 공통 계정

## 이메일
기존 `approval-email` Edge Function은 단계명을 DB에서 읽으므로 재배포가 필요하지 않습니다.
SQL 적용 후 이메일 순서는 자동으로 `부서장 → 해당부서 임원 → 주관부서 → 대표이사`가 됩니다.

## 참고
결재자가 아직 연결되지 않은 단계는 `결재자 미지정`으로 표시되고, 해당 단계에서 흐름이 멈춥니다. 계정을 연결하면 현재 대기 건이 자동 재배정되고 이메일 큐가 생성됩니다.
