# V2.6.7 — 제안서 본문 편집기 전체 정리

기준 버전: V2.6.6. 표 삽입 버튼뿐 아니라 현재 문제점 / 개선방안 / 기대효과의 편집도구 전체를 정리했습니다.

## 적용할 파일 — 3개

```text
index.html
js/app.js
css/styles.css
```

현재 저장소의 **같은 경로**에 교체하세요. `js/app.js`를 저장소 최상위의 `app.js`와 혼동하지 마세요.
ZIP 자체를 GitHub에 올리는 것이 아니라 압축을 풀어 위 파일들을 해당 경로에 올립니다.
세 파일을 함께 반영한 뒤 GitHub Pages 배포가 끝나면 Ctrl+F5로 새로고침하세요.
평소 툴바에 `글자`, `문단`, `표 삽입`, `크게 보기`가 나타나면 새 화면입니다.

**이번 버전은 SQL 실행이 필요 없습니다.**
`js/config.js`, `js/services/store.js`, `js/core.js`와 SQL은 변경하지 않았습니다.
기존 평가 기준, 결재·반려·재상신 로직, 저장 권한은 이번 변경 대상이 아닙니다.
운영 사이트에 자동 반영된 파일이 아닙니다. 위 세 파일을 적용해야 반영됩니다.

## 새 편집도구

| 메뉴 | 기능 |
|---|---|
| 글자 | 글자 크기, 굵게, 기울임, 밑줄 |
| 문단 | 왼쪽·가운데·오른쪽 정렬, 줄 간격, 글머리·번호 목록 |
| 표 삽입 | 버튼 아래에 격자 선택창 표시. 격자는 8행×10열까지 빠르게 선택. 숫자는 각각 1~20까지 직접 입력 |
| 표 편집 | 표 셀을 클릭했을 때만 표시. 행·열 추가/삭제, 열 이동, 열 너비, 행 높이, 셀 여백, 표 너비/위치 |
| 크게 보기 | 같은 내용을 넓은 화면에서 편집. 편집 마치기 또는 Esc로 원래 작성칸으로 복귀 |

- 한 번에 메뉴 한 개만 표시합니다. 바깥 클릭, Esc, 닫기 버튼으로 닫습니다.
- `행+`, `열−` 같은 축약어 대신 `아래 행 추가`, `선택 열 삭제`처럼 적용 대상을 표시합니다.
- 메뉴를 클릭해도 편집 중인 글자·셀의 선택 위치를 복원합니다.
- 메뉴의 숫자 입력은 본문 제출을 발생시키지 않습니다. 닫힌 설정창의 입력칸은 제출 검증에서 제외합니다.
- 좁은 화면에서 메뉴를 화면 안에 맞추고, 긴 설정창은 내부 스크롤로 확인합니다.
- 표 너비를 60%·80% 또는 내용에 맞춤으로 줄이면 표 위치의 좌우 차이를 확인할 수 있습니다.
- 글자 크기, 줄 간격, 셀 여백, 행 높이, 표 너비/위치 등 허용 서식은 기존 HTML 필드에 저장합니다.
- '크게 보기'에서 편집을 마쳤다는 것은 **제안서 저장 완료가 아닙니다.** 마지막에 기존 제안 제출/수정 저장 버튼을 눌러야 저장됩니다.

## 범위 및 제한

- 새 제안과 기존 제안 수정 화면 모두 동일한 편집기를 사용합니다. 기존 제안의 수정 가능 여부는 기존 권한/결재 규칙을 그대로 따릅니다.
- 병합된 셀이 있는 표는 행·열 추가/삭제/이동/열 너비 변경을 차단해 표 구조가 손상되지 않게 했습니다. 글자, 표 위치, 표 여백 등은 편집할 수 있습니다.
- 셀 병합/분할, 마우스 드래그로 열 경계 조절 기능을 추가한 버전은 아닙니다.
- 운영 Supabase 데이터에는 접속하거나 쓰지 않았습니다. 아래 검증은 로컬 브라우저와 데모 저장소 기준입니다.
